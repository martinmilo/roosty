# Record 1b: defects found running record 1 on a real project

Date: 2026-10-10 15:47. Supersedes, in record 1a (`2026-10-10-1434-trial-layout.md`), the
layout of WATCH OUT, of WORK WITH THIS PROJECT, of environments, of process descriptions in
the overview and of `try` in `show`, and extends the validate checks. Everything else in
records 1 and 1a stands.

Record 1 was implemented and run on a trial project. The owner brought back ten defects: seven in what is
printed and checked, three in what FORMATS.md fails to explain.

## Decided

### WATCH OUT

Each item starts with `- ` after the indent of two. An item wraps at 80 with a hanging
indent: continuation lines start under the first word, at column 5.

```
WATCH OUT
  - Stripe runs in test mode on staging; never use a real card there.
  - The reminder job runs at 18:00 in the studio's time zone, not UTC, so a
    booking made later that evening for the next morning gets no reminder.
```

`validate` reports an item longer than 160 characters, and a list of more than 7 items,
each as a finding naming `project.yml`, `watch_out` and the limit. On the trial project an agent wrote ten
paragraphs there. WATCH OUT is for the handful of things that bite anyone working on the
project; detail about one behaviour belongs in that process's record. 160 and 7 are allowed;
161 and 8 are not. The overview prints whatever is there; only `validate` complains.

### WORK WITH THIS PROJECT

Operations only. The label column is as wide as the longest operation label plus four, after
the indent of two. The command is on the label's line. A note is never on that line: it
starts on the following line in the command's column and wraps at 80 with continuation lines
in the same column. The section is left out when there are no operations.

```
WORK WITH THIS PROJECT
  start     bin/dev
  test      bin/rails test
  deploy    bin/kamal deploy
            asks for the production vault password
```

On the trial project, notes on the command's line ran past 80 columns and the one rule that let a line pass
80 is gone with them: nothing in the overview passes 80 any more.

### ENVIRONMENTS

A section of its own, after WORK WITH THIS PROJECT, same label rule (longest environment
label plus four). Left out when there are no environments. Environments and operations no
longer share a list, so one section's width no longer depends on the other's labels.

```
ENVIRONMENTS
  staging       staging.atelier.example (Hetzner)
  production    atelier.example (Hetzner)
```

### Process descriptions in the overview

A description wraps under its column, the id column, at 80. It is never cut; the `...` rule
of record 1a is withdrawn. On the trial project the cut lost the point of the sentence.

```
    cancel-booking     Cancel a booking and free the place for the next person
                       on the waiting list.
```

### `try` in `show`

Each line of `try` is printed after the label column exactly as written: leading spaces and
runs of spaces are kept, no line is wrapped or cut, so a line may pass 80 columns. This is
the one place in `show` that may. On the trial project an indented code snippet had been re-flowed into
prose. A blank line inside `try` is printed as an empty line.

### validate: unknown keys and key paths

- An unknown key, at any level of `project.yml` or a process record, is a finding naming the
  file and the key. Every map in FORMATS.md is closed: an outcome has `when` and `then`, a
  `files` item `path` and `note`, an operation `command` and `note`. Without this an agent's
  typo (`outcome:` for `outcomes:`) passes `validate` and the record silently shows nothing.
- A finding names a key as a dotted path from the top of the file, with no trailing dot:
  `outcomes.refunded: must be a map`, `outcomes.refunded.because: unknown key`. The path of
  an item inside a list (`watch_out`, `why`, `files`, `entrypoints`) is not pinned by a test;
  the tests only require the key.
